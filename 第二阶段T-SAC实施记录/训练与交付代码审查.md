# 训练与交付代码审查

审查日期：2026-09-20。审查范围：新实现 `horizon_tsac_20260920` 的 train.py、evaluate.py、artifacts.py、export.py，以及它们与 Recorder、CoverageScenario 的接口。审查人是独立于这些文件实现者的子代理；修复由文件负责人完成，本文件记录复核证据。原 `sac_fyh_io` 及历史产物没有参与修改。

## 结论

本次审查发现并闭环了数据清单使用不一致、新 schema 来源 hash 混用、交接频率/状态校验不足、场景标识越出输出目录、推理计时混入遥测成本等问题。独立新增的 `test_delivery_review.py` 五项测试全部通过；它包含一次明确标记的微型 fixture 训练与独立评估，只用于验证交付链路，未把其结果作为训练性能证据。

检查点保存采用不可变历史存档及 hash sidecar，恢复对照使用同一数据划分与语义配置，并保存 RNG、replay、采样器、优化器和 durable_event_seq。现有集成回归另验证回合边界续训的模型参数一致性；这不是对跨硬件位级一致或任意中途恢复的保证。

## 已修复发现

1. **P1：新 schema JSON 的来源 hash 与输入文件 hash 混用。** 原 evaluate_run 将 CoverageScenario.source_hash 与数据清单的 JSON 字节 hash 比较；前者可能是上游数据血缘 hash，合法的 coverage.v2 JSON 会被拒绝。独立路径隔离测试真实复现此故障。修复后使用已读取 source_path 的文件 hash 与 record 比较，保留场景源 hash 的血缘语义。`test_evaluation_scenario_identity_cannot_escape_output` 已完整通过微型 train→evaluate→export。

2. **P1：核验的数据清单不是后续实际迭代的副本。** 原评估核验数据划分.json，随后迭代运行清单内嵌的另一份 records。修复后直接迭代 prepare_dataset 返回值，同时检查内嵌副本、冻结文件和清单 hash 一致。对应代码在 [evaluate.py](<D:/graduate/PPO4090/implementations/horizon_tsac_20260920/evaluate.py>)。

3. **P2：重新签名后的交接文件仍可带错频率网格或未知状态。** 单纯 NPZ 文件 hash 正确不足以保证物理语义正确。修复后检查全部字段白名单、shape、数值/整数/布尔 dtype、有限性、非负性、状态枚举及 demand mask，并将 frequency_hz 对照配置中的槽中心频率。独立测试故意改变数组并更新文件 SHA，确认错误频率、状态=99、数值型 X、非有限速率均被拒绝。

4. **P2：scenario_id 被直接作为输出子路径。** 标准场景 ID 允许普通字符串，含 `../` 时可逃出评估策略目录。修复后目录使用场景 ID 的 SHA 摘要，原 ID 仅存元数据。独立测试用 `../../../escaped-output` 作为合法身份完成评估，确认文件仅写入 `random/场景-摘要/`，外部同名目录没有创建。

5. **P2：推理成本混入日志序列化/排队。** 原 inference_seconds 围住整段含 Recorder 的循环。修复后分别记录 policy_decision_seconds、动作选择加环境计算的 inference_seconds、含日志的 rollout_seconds。报告中的“整景耗时”须依对应字段解释，不用一个字段同时代表纯网络推理和端到端吞吐。

## 接口复核

- 检查点引用指向 `检查点存档/<checkpoint_id>/检查点.pt`，当前根目录“检查点.pt”是最新入口；替换最新入口不会更改旧工件内容。每份 sidecar 与配置/划分/场景快照均登记为独立 artifact。
- 评估使用 phase=validation/test，Recorder.end_episode 已支持显式 phase，不能把评估终局指标记到训练系列。看板配对接口排除 train 回合，并使用实际 mean_satisfaction 字段。
- 训练在完整回合结束后保存精确恢复检查点；外部 max_env_steps 截断不会冒充完整边界。Recorder failure 时保留已提交前缀，控制器异常流程保留上一有效边界引用。
- 第三阶段交接使用 allow_pickle=False 的 NPZ 和完整场景/配置，重新加载后独立计算功率、速率与 SINR。传输 hash、字段语义和物理复算是三项不同检查。
- 新 schema 评估的服务顺序使用场景及训练 seed 派生的局部随机源，各策略同场景对齐；这避免 random 服务顺序配置下策略对照拿到不同顺序。
