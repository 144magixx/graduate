## 每次运行冻结什么

创建 run 时，从本次精确清单与相应规格重算审计，并将以下两份文件写入 run 根目录：

- `训练场景覆盖规格.yaml`
- `训练场景覆盖审计.json`

运行清单的 `coverage_snapshot` 提供固定作用域、数据清单 hash，以及每份工件的相对路径、SHA256、artifact_id 和 kind。Recorder 将两者登记为工件，SQLite 一致性离线导出只复制本 run 所引用的文件。工作区后续修改规格或审计，不会改变已保存 run 的证据。

run 审计包含 `source_manifest_hash`、`coverage_spec_hash`、规格来源、运行预算/槽数及标签可用性。运行物理预算与规格不匹配时，不能宣称严格覆盖验收通过。静态审计里的采集/更新总数设为 null，指向 checkpoint/优化日志/运行结果中的实际计数，不把冻结时的 0 冒充整次训练的最终计数。
