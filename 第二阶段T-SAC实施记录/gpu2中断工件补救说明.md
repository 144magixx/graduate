# gpu2中断工件补救说明

**备用故障处理说明；当前没有故障，不执行补救。已部署的恢复监督脚本保持冻结。P2尚未代码修复，本说明仅提供异常后的人工核验与归档兜底。**

## 已知问题与触发条件

[监督脚本](D:/graduate/第二阶段T-SAC实施记录/gpu2恢复监督脚本.py:339)在最终复制前递归检查整个run的数据库状态。评价被超时强杀后，评价SQLite可能保留`active/running`标签；即使训练已经成功结束，这个失效评价子树也会阻止整个训练run归档。训练自身被强杀时，其数据库也可能保留上述标签。

只有明确出现timeout、异常退出或“活跃数据库导致最终复制失败”时才进入本流程。训练仍正常运行、整体`finished=false`、某项评价尚未完成，均不是补救触发条件。既有不可变检查点的独立同步另行核验，不把最终run复制失败等同于全部检查点丢失。

## 1. 先确认相关自有进程确已退出

以[恢复计划](D:/graduate/第二阶段T-SAC实施记录/gpu2恢复计划.json)中的`node_project/control_dir`、`恢复进度.json`、对应评价请求和日志为范围，核对本次子进程的PID、进程组、启动时间及完整命令。当前作业步骤为`206357.1`；不按Python进程名批量终止，不触碰其他作业。

冻结的Linux启动器为孩子建立独立session，通常PGID等于孩子PID。仍须核实身份和进程组内是否还有训练worker/SQLite writer，不能仅看进程组leader消失。评价结束后`active_evaluation`可能已从最新进度中移除，应结合此前快照与作业进程记录确认，不能把缺失字段当作退出证据；也不能把后来复用的同号PID认作原孩子。

只读检查可使用带明确自有PID/PGID的`ps`、`pgrep -g`及`scontrol listpids 206357.1`，并核查相关数据库的打开句柄。确认相关进程组已空、没有其他写入者后，才允许处理其数据库。如果训练仍运行，只能处理已经退出的失效评价，不得复制活跃训练根；身份或写入状态无法确认时停止，交由主任务继续核查。

## 2. 保留原始失败证据，不修改原目录

在新的节点本地暂存目录及新的home“中断补救”目录建立独立案例，记录源run/trial/parent checkpoint、故障评价ID、请求、退出码、timeout、PID/PGID核查时间、原状态和源路径。只处理解析后仍位于指定节点项目下的路径。

复制保留原日志、请求/结果/异常JSON、清单、检查点sidecar及相关文件。对已经确认静止的失效数据库，可将原SQLite及实际存在的`-wal/-shm`作为一组失败原件封存，并记录复制前后SHA；若文件仍变化，停止复制。**不移动、删除或改写原失效子树，不覆盖原进度、历史归档或原失败记录。**

`active/running`是保存的逻辑状态，不能仅为通过检查而执行`UPDATE ... completed`。进程已退出也不代表该回合、事务尾部或评价已完整完成。

## 3. 分开归档成功部分与中断部分

- **训练已正常结束，仅嵌套评价失效：**确认训练根数据库及其他拟归档数据库均已关闭。在新暂存树中复制训练清单、配置/数据划分、已核SHA检查点、场景与日志，以及其他已关闭评价；按明确路径排除失效评价子树。失效子树另存为失败证据。再归档这份已关闭的过滤副本，附“包含/排除范围及原因”清单。不要把过滤副本冒称为包含全部评价的完整成功run，也不要用原全量哈希清单替代新副本的范围与SHA清单。
- **训练本身异常退出：**确认所有相关写入者退出后，使用SQLite的backup接口在节点本地产生一致的已提交数据快照，再核对`integrity_check`和已保存事件范围。保留数据库原来的`active/running`标签，将外部归档类型明确标为“静止但未正常终结的失败快照”。不要伪造训练完成、补写缺失回合或从日志猜造模型检查点。若backup失败，保留静止原件和错误，不能宣称数据完整。
- **参考模型的CPU评价：**只复制已经关闭的独立评价输出子树，不复制参考根训练数据库。补跑评价如有必要，应使用新的本地评价目录/attempt、原冻结检查点及全15景validation、policy-only协议；保留失败attempt，不重启训练、不改参数、不使用test选参。

每份新归档保留原run/trial和失败谱系，并另列归档案例ID，避免被算成新的训练种子。原监督结果若为failed，保持原样；另写补救记录说明“哪些数据已安全归档、哪些评价仍缺失”，不把原失败改成completed。

## 4. 结束检查与剩余风险

逐文件核对新副本的字节数与SHA、SQLite完整性、数据/检查点身份和实际保存范围。只有原本已正常完成的评价才能计入完成结果；中断评价须保持缺失/失败，不能补零、补造分数或并入完整15景比较。

本说明不会消除冻结脚本的递归状态检查P2。异常后仍需明确核验与独立归档；无法证明进程退出、数据仍在变化、SQLite损坏，或节点临时数据已丢失时，不能安全自动补救，应保留已有home检查点及证据并报告缺口。当前正常训练无需任何补救操作，也不因这份说明延长预算或变更部署。
