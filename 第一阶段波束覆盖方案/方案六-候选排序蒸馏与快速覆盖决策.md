# 方案六：候选排序蒸馏与快速覆盖决策

编制日期：2026-09-20。定位：第一阶段可选的效率扩展；复用已经正确的候选生成器与第二阶段评价，不作为必须完成的主研究路线。

配套文件：[第一阶段方案总览（面向研究者）](<D:/graduate/第一阶段波束覆盖方案/第一阶段方案总览（面向研究者）.md>)；[第一阶段接口与实施规范（面向实施Agent）](<D:/graduate/第一阶段波束覆盖方案/第一阶段接口与实施规范（面向实施Agent）.md>)。

## 1. 适用问题与研究假说

当一个 root 有几十到几百个合法布局时，对每个候选完整运行 Horizon T-SAC 可能成为主要成本。本方案学习候选的相对优劣，把昂贵评价预算集中到少量更有希望的布局。

研究假说是：离线积累的精确下游评价可以训练一个排序器，在独立 root 上保持较高的优良候选召回率，减少在线真评次数并控制最终服务损失。

这里的“蒸馏”是把慢搜索与冻结第二阶段得到的候选偏好压缩成快速排序模型，不意味着教师给出了全局最优布局。

## 2. 为什么学习排序而不是直接回归布局

同一物理布局可以有多种波束排列，等价覆盖还可能有不同中心组合；直接把长度可变的中心坐标拼成一个向量回归，会混入排列歧义和多解问题。

本方案把可行性留给经过验证的生成器，只学习 `score(root,candidate)`。输出是已有候选的排序和少量待真评候选，而非凭网络直接生成未经校验的中心、宽度或 assignment。

若后续研究真正的生成模型，应作为另一套方法处理集合匹配、多解、覆盖修复及分布外可行性，不能直接延用本方案结论。

## 3. 教师数据如何产生

对训练 root 调用容量约束聚类、局部搜索或 PPO，保存每个合法 `CoverageCandidate` 的生成器版本、参数、seed、完整 beam_table、assignment 和候选 hash。

统一冻结 Horizon T-SAC 权重、配置、服务顺序规则、预算和物理版本，对每个候选完成分配并以当前物理内核全量重算。

标签主值使用 `J_root=Σ_b min(R_b,D_b)/Σ_u d_u`，并保留未覆盖量、真评耗时和失败状态。不同覆盖候选不能以逐束平均 U 充当共同业务收益标签。

没有真实 root/assignment 时可以生成可追溯合成数据，但须标明合成，并禁止从历史 CSV 拆分出臆造用户作为真实标签来源。

教师候选池有生成偏差。应包含多种初值、较弱但合法的候选和困难场景，避免只存最优结果，使排序器从未见过坏布局。

## 4. 排序器的输入与结构

root 输入包含位置与需求的集合/网格摘要、总需求、空间集中度及已知服务域；候选输入包含束中心、固定宽度、聚合负载、覆盖率、归属统计和几何邻接。

允许使用便宜的容量/耦合代理，但在线输入不得使用尚未真评得到的 T-SAC 终局速率、最终功率或 `J_root`，否则构成标签泄漏且失去提速意义。

首版先做共享 MLP 加集合池化或树模型，必要时再加轻量图编码器。学习器的目标是候选排序，不需要复制第二阶段完整 Transformer。

候选节点使用共享参数并池化，禁止把任意 beam_id 当作有序位置特征。打乱行序后，物理等价候选应得到数值一致或容差内一致的分数。

## 5. 成对排序目标

在同一 root 中选择两个候选 `L_i,L_j`，其教师评价差为 `Δ_ij=J_root(L_i)−J_root(L_j)`，网络分数为 `s_i,s_j`：

```text
y_ij = sign(Δ_ij)
loss_pair = log(1 + exp[−y_ij·(s_i−s_j)])
weight_ij = min(|Δ_ij| / δ_scale, w_max)
loss = weighted_mean(loss_pair)
```

当 `|Δ_ij|≤δ_tie` 时视为近似并列，跳过或用单独的并列损失，避免逼迫模型拟合没有实际意义的微小差距。

`δ_tie` 根据评价确定性和业务容差预先定义，不能根据测试结果反复调整。若教师存在随机采样噪声，先固定种子或多次评估，再确定偏好可信度。

每次先均匀采样 root，再在该 root 内采样候选对，避免候选更多的场景主导训练。验证与测试按 root/谱系划分，同root的所有候选留在同一分区。

## 6. 在线决策流程与安全回退

第一步生成合法候选并检查覆盖、指向域、需求守恒和归属；第二步排序；第三步对 top-k 候选完整调用冻结第二阶段；第四步按真评 `J_root` 选择最终布局。

始终在真评集合加入一个已知基线候选；若存在上一周期布局且它在当前 root 下仍可行，也可以加入回退集合。合并去重后记录实际真评次数。

排序分数只决定评价次序，不充当最终交付业务值。完整真评和约束复核不过关的候选不得因预测分数高而被选中。

若所有新候选失败，返回已验证的可行基线并记录退回原因；若基线也不可行则明确报告失败。不能把模型低置信度转换成虚假的成功状态。

首版固定 k；后续可根据验证集上的 top-k 召回曲线设置分档 k。模型不确定性可作启发式扩容信号，不直接解释为已校准的正确率保证。

## 7. 与现有第二阶段保持一致

标准接口使用 `CoverageScenario` 的真实实体集合和 `CoverageCandidate` 的归属契约，不填充、截断或复制到旧的 200 行模板。

首版固定宽度和峰值增益，遵循当前地面角直径语义。候选层不能借排序网络绕过未验收的变宽—天线增益耦合。

group 和 service_order 按共同接口规范生成，禁止候选通过重编 beam_id 偷偷改变频组以获得额外优势；编号和映射策略在所有生成器间一致。

教师权重、配置或物理模型变更后，旧标签至少要重新抽样审计；跨版本标签未经校准不能混作同一目标。标签缓存键必须含这些版本的 hash。

现有 smoke checkpoint 只够验证训练数据流和接口，不足以作为优越资源分配器的教师证据；教师质量不足时，排序器只会高效复现其偏差。

## 8. 核心指标与实验

同一候选池内定义 `regret=J_best_in_pool−J_selected`，同时报告绝对 `J_root`。`J_best_in_pool` 只是枚举候选池的最佳值，不称全局最优或理论上界。

报告 top-k 优良候选召回率、平均/高分位 regret、完整端到端时延、真评次数、基线回退率和失败率。只报排序相关系数不足以证明选型质量。

1. 随机选 k、廉价几何评分选 k、容量代理评分选 k、学习排序选 k，与全候选枚举比较。
2. k 取若干递增值，绘制服务损失—时延曲线；各算法共享生成器和候选池。
3. 比较成对排序与点值回归 `J_root`，验证排序目标是否更适合本任务。
4. 比较简单特征模型、集合模型与图模型，统计在线特征提取成本。
5. 比较只用最佳候选附近数据与包含弱候选/困难样本的数据，验证训练池偏差。
6. 留出未见业务规模、生成器族或热点结构，检验排序器是否只识别生成器标签。

每次对照都在相同 root 上成对比较；学习方法先多种子筛选，再按独立 root 汇总统计。测试标签不能反哺排序器或候选生成器。

## 9. 复杂度与收益兑现条件

设候选数 M、排序及特征开销 `C_rank`、真评成本 `C_alloc(B)`，枚举在线成本约为 `M·C_alloc(B)`；本方案约为 `C_rank+k·C_alloc(B)`，另加共同候选生成成本。

只有减少的真评成本大于排序和特征开销时才有在线收益；若候选生成才是主瓶颈，则排序蒸馏帮助有限，须先测量时间分解。

离线标注成本约为训练 root 数乘候选数乘真评成本，再加排序训练。报告总成本和复用次数，不能只展示推理毫秒数隐藏教师计算。

首个小原型可选每root 16–32 个候选、k=2/4/8 做可行性筛选；这些是算力预算建议，实际候选数和阈值由验证曲线决定。

## 10. MVP 与停损条件

MVP 先复用一个可靠生成器，积累合法候选及真评标签，实现无终局特征泄漏的简单排序器、top-k 真评、强制加入基线和全量复核。

验收包含 root 切分一致、候选排列不变性、缓存版本隔离、弱候选保留、特征可在线计算、回退可复现，以及最终输出与真评记录一致。

若学习排序不能超过同 k 的容量代理排序，停止增加网络复杂度；保留标签库作为其他方案的共同评价资源。

若实际时延优势很小或 regret 在未见场景上失控，提高 k 或退回全枚举，不能为追求速度跳过最终复核。

若标注成本无法在预计实验或运行次数内摊销，本方案暂缓，优先完成第一阶段可行生成器和主要覆盖算法。

## 11. 结论边界与代码依据

本路线的可验证贡献是“在明确候选池与预算下，降低评价次数并控制选择损失”。它不证明新的覆盖物理模型，也不证明排序模型能在任意业务域中泛化。
