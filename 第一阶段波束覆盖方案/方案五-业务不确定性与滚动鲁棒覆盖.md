# 方案五：业务不确定性与滚动鲁棒覆盖

编制日期：2026-09-20。定位：在静态覆盖主线成立后研究需求预测误差与服务稳定性；本文件不宣称现有环境已经支持动态队列、雨衰或真实滚动运行。

配套文件：[第一阶段方案总览（面向研究者）](<D:/graduate/第一阶段波束覆盖方案/第一阶段方案总览（面向研究者）.md>)；[第一阶段接口与实施规范（面向实施Agent）](<D:/graduate/第一阶段波束覆盖方案/第一阶段接口与实施规范（面向实施Agent）.md>)。

## 1. 核心想法与适用场景

只按平均预测需求设计的布局，可能在热点稍有变化时出现严重缺口。本方案为同一空间业务根场景构造多组需求扰动，选择平均服务与坏情形表现更稳的覆盖布局。

研究假说是：在相同波束数、宽度、资源预算和冻结分配策略下，面向需求误差的布局选择能以可解释的平均收益代价改善服务下尾，而不只是增加覆盖冗余。

这套路线适合业务预测误差较大、覆盖更新代价高、业务热点存在重复模式的情形。没有预测或扰动来源时，先研究受控合成不确定性，不能包装为真实业务预测。

## 2. 分两批实施，避免任务失控

第一批只做**静态需求不确定性下的覆盖选择**：位置固定、候选几何固定，一次求出一个布局，再在多个静态需求样本上独立调用第二阶段。

第二批可扩展为**连续业务快照上的滚动覆盖**：每个慢时标观察当前信息，选择未来一段时间使用的布局，下游仍逐快照独立分配。

第二批初始也不引入真实队列、跨时隙积压、时延约束、波束跳变或雨衰模型。若以后引入，必须新建数据与环境语义并重新验收，不能把现有静态回合顺序当成时间演化。

## 3. 不确定性集合如何构造

固定 root 的用户 ID 和位置，建立名义需求 `d̄_u`。先从训练数据估计或明确配置全局总量误差、空间热点相关误差和个体残差，再生成 `d_u^(k)≥0`。

示例生成式为 `d_u^(k)=d̄_u·exp(z_global^(k)+z_region(u)^(k)+ε_u^(k))`，再按实验规则选择是否保持总需求。若需均值校准，须显式补偿指数变换的均值漂移。

均值保持误差、总需求增长、热点位置迁移是不同压力轴。首批仅用前两者；位置迁移需要重新检查覆盖与 assignment，不能沿用需求增强函数冒充几何增强。

所有候选共享完全相同的 K 组需求样本与权重 `w_k`，权重非负且和为 1。扰动参数只用训练集拟合，验证集选风险系数，测试集留作最终评估。

正需求变成零或零需求转正时，同步重建 `demand_mask` 和服务顺序；不能把突然有需求的真实实体当作 padding。未归属需求仍进入 root 总需求。

## 4. 鲁棒目标：平均表现与坏情形缺口

每个候选布局 L、每个需求样本 k 分别得到冻结第二阶段输出，并定义：

```text
J_k(L) = Σ_b min(R_b^(k)(L), D_b^(k)(L)) / Σ_u d_u^(k)
loss_k(L) = 1 − J_k(L)
CVaR_α(loss) = min_η [η + Σ_k w_k·max(loss_k−η,0)/(1−α)]
L* = argmin_L {Σ_k w_k·loss_k(L) + λ·CVaR_α(loss(L)) + μ·C_move(L)}
```

`α∈(0,1)` 表示损失上尾水平；例如 α=0.9 关注最坏约 10% 的损失。λ 和 μ 的含义必须随报告公开，不能只报单个最优综合分数。

若有限样本 K 很小，极端 CVaR 几乎退化为一两个样本，估计方差很高。先用中等 α 与样本数敏感性分析，逐步增加独立测试扰动。

总需求为零的样本按无业务单列，不将其设为 1 混入平均值。所有候选在同一 k 中共享分母；不同 k 的需求变化应另外报告 bps 缺口，避免只看比值掩盖大负荷。

上述目标是对当前聚合物理模型的样本风险优化，不是对任意分布的严格鲁棒保证，也不保证每个用户 QoS 或真实系统 outage 上界。

## 5. 候选生成与搜索

直接复用其他方案的需求聚类、容量约束、局部搜索或 PPO 生成器；首版对一个可控大小的合法候选池进行场景复评即可，不必另造复杂 DRL。

第一步生成名义布局及少量热点偏移布局；第二步几何与守恒校验；第三步在共同需求样本上评价；第四步按风险目标排序并保留均值—尾部的 Pareto 候选。

昂贵评价前可用容量代理筛掉明显弱候选，但最终入选布局必须调用冻结第二阶段全量重算。筛选保留率和漏掉好候选的比例都要记录。

搜索中不得给困难样本偷偷扩宽、增加波束、改变总功率或删除 root 用户。候选几何不可行应明确淘汰，并报告发生频率。

## 6. 与 Horizon T-SAC 的实际接口

使用 `RootScene → CoverageCandidate → CoverageScenario`。每个需求样本中按 `assignment.T @ demand` 重算束需求，按未归属比例重算 `uncovered_demand_bps`。

现有 `augment_root_candidates` 展示了同root候选共享需求扰动的接口思路，但它只实现特定缩放与噪声规则，不等于本文完整的相关不确定性生成器。

每个候选的名义频组按冻结配置规则一次生成；需求扰动期间保留该映射，仅按已约定规则更新服务顺序，避免把风险收益混入重新着色收益。

冻结第二阶段 policy、config、预算、宽度语义和评价版本。支持可变实体不等于已证明所有规模都可泛化；首批选择已验证的可行范围。

当前宽度为地面角直径且峰值增益固定，首版固定宽度；物理快照使用当前静态干扰模型，不声称已有天气变化或载荷可重构增益模型。

## 7. 可选扩展：滚动和事件触发

当静态鲁棒选择有效后，为完整轨迹构造时序一致的 `root_t`，保留用户/业务稳定 ID、时间戳及可用信息边界。预测器不能读取未来真实需求。

每隔 Tc 个快照进行一次覆盖决策，后续 Tr 快照调用冻结资源分配；`Tc>Tr` 是新增实验调度约定，须记录实际单位和更新耗时。

滚动窗口中只执行当前选定布局，下一决策点重新预测；在候选目标中增加中心位移、关联变化和重构次数。先在明确定义的模拟成本下研究，不虚构真实载荷切换时间。

事件触发可用“当前布局预测的缺口风险超过阈值”或“相对名义需求偏差超过阈值”；阈值在验证轨迹冻结，并设置最短保持期以抑制频繁切换。

更新耗时超预算或新布局未通过校验时保留上一可行布局并记录原因。若上一布局因位置变化失去覆盖，必须显式报告覆盖违约，不能继续把它称为可行回退。

## 8. 必做基线与消融

1. 按名义需求优化、按平均样本损失优化、按最坏样本损失优化、均值加 CVaR，使用同一候选池比较。
2. 各方案使用同样的场景样本与下游调用预算，另给“额外计算换收益”的完整曲线。
3. K、α、λ 的敏感性；独立个体扰动与空间相关扰动比较；均值校准与未校准模型分开。
4. 分布内误差、未见总负荷和更强热点相关误差的压力测试，检验风险收益能否跨误差模型保持。
5. 若做滚动，再比较固定布局、固定周期名义更新、固定周期鲁棒更新与事件触发鲁棒更新。
6. 如有预测器，比较持续值预测与同预算预测器；未来真实需求仅作离线信息参照，不称可部署方案。

核心指标为 `J_root` 均值、下尾分位、缺口 bps 的均值与上尾、覆盖违约率、重构次数和完整时延。逐束 U 仅作同一布局内的辅助诊断。

## 9. 统计、复杂度与成本

设合法候选数 M、需求样本数 K、第二阶段评价成本 `C_alloc(B)`，首版枚举成本约为 `M·K·C_alloc(B)`。部署速度优势必须扣除不确定性生成、候选校验和全量复核。

首个原型可从 M=8–16、K=16–32 起步验证数据流；这些是预算建议而非足够估计尾风险的统计保证。最终 K 通过收敛曲线和独立评估误差确定。

缓存不得把不同扰动样本误视为同一输入；候选几何相同也可能因需求、服务顺序和分配动作不同而得到不同速率。

训练、验证和测试按原始 root 或完整轨迹分组；同一 root 的需求扰动不跨集合。置信区间以独立 root/轨迹为单位，不把相关扰动当成完全独立样本。

## 10. 最小可运行版本与止损

MVP 只包含合成静态 root、两类需求误差、同候选池枚举、冻结 T-SAC、多样本 `J_root` 与经验 CVaR，并附名义/平均损失基线。

首先验证同root共享样本、需求守恒、组映射冻结、风险公式的简单手算例子、空业务分支和候选失败处理；随后才扩大场景库。

如果尾部提升只来自明显牺牲均值或大幅增加调用成本，应呈现 Pareto 权衡，不宣布普遍优越；没有稳定收益时保留为压力测试协议。

如果误差模型稍变就失效，先缩小结论适用域，不继续叠加滚动 PPO。静态风险结果未成立前，停止开发动态队列、雨衰和复杂预测网络。

真实上游 root/assignment 未取得时，仅能开展带版本、种子和生成规则的合成研究；合成场景不是历史 CSV 原始用户恢复，也不能计入真实来源验收。
