# 方案四：残差式图策略与约束 PPO

编制日期：2026-09-20。定位：第一阶段的主要 DRL 候选路线；本文件是待验证设计，不代表已训练或已证明性能提升。

配套文件：[第一阶段方案总览（面向研究者）](<D:/graduate/第一阶段波束覆盖方案/第一阶段方案总览（面向研究者）.md>)；[第一阶段接口与实施规范（面向实施Agent）](<D:/graduate/第一阶段波束覆盖方案/第一阶段接口与实施规范（面向实施Agent）.md>)。

## 1. 这套方案解决什么问题

让策略从一个已经满足覆盖约束的布局出发，学习少量有价值的中心调整。聚类、归属和确定性修复承担可行性，PPO 决定调整哪个波束、选择哪个完整候选、何时停止。

研究假说是：在业务热点、波束重叠和有限计算预算并存时，利用邻域干扰结构的多步调整，比只看即时增益的贪心更能改善下游可交付业务；这是一条需要实验支持的假说。

首版固定真实波束实体数和各束宽度，只优化中心与由几何决定的业务归属；归属变化后的正需求束数另记，不能把它等同于实体数。分裂、合并和变宽另作扩展，否则难以分清学习收益来自哪里。

潜在贡献应落在“同等下游调用预算下，约束内的序贯布局调整改善服务效果”，不能把采用 PPO 或图网络本身写成新颖性。

## 2. 和当前第二阶段的边界

第二阶段使用 `implementations/horizon_tsac_20260920/`，以 `CoverageScenario` 接收可变数量的真实实体，不能恢复为旧的 200 行强制模板。

每个布局输出 `CoverageCandidate`，通过 `root_scene_id` 关联同一个 `RootScene`，保存稳定 `beam_id`、`assignment`、聚合需求和未覆盖需求；先通过 `candidate.validate(root, config)` 再进入资源分配。

第一阶段训练期间冻结 Horizon T-SAC 的策略权重、完整配置、服务顺序规则和物理版本。首轮串联可用 smoke checkpoint 验证流程，但不能据此判断覆盖方案优劣或第二阶段性能。

当前配置的宽度是 `ground_angular_diameter_deg`，峰值增益为显式配置值；变宽与硬件增益耦合尚未验收。首版保持宽度和增益固定，不利用扩大宽度制造虚假收益。

聚合束中心代表接收位置，`J_root` 仍是聚合服务代理。没有逐用户调度及边缘信道验收，不能把提升直接称为每个用户的速率或 QoS 改善。

## 3. 状态：根业务、当前布局和可执行候选

波束节点包含中心、固定宽度、聚合需求、容量代理、冻结 T-SAC 上次评价得到的满足度、与初始布局的位移，以及剩余调整步数。

边特征包含球面角距离、覆盖交叠、同极化关系及由现有物理内核计算的方向耦合。图用于策略编码，不据此删除物理评价中的任何干扰源。

原始需求点可以先做固定网格统计或按归属聚合；同时保存完整 root 供守恒和覆盖检查。需求长尾、未覆盖量、总需求与规模均进入全局摘要。

首个实现先用共享 MLP 加集合池化；图编码器作为增量版本加入。避免一开始同时换状态、动作、奖励和网络，导致无法解释实验差异。

束编号只标识实体，不作位置嵌入。排列输入行并同步变换归属与 ID 后，决策分布应保持相同物理含义。

## 4. 动作：有限联合候选加 STOP

每步构造完整候选 `a=(beam_id, displacement_id, assignment_rule_id)`，候选坐标在球面或局部切平面上定义；首版最多使用少量方向和两档位移。

位移后按冻结规则重新归属，并调用确定性修复。修复可以回退、交换边界归属或执行受限中心微调，但不得偷偷改变束数、宽度、覆盖目标或物理配置。

动作 mask 检查整个候选执行结果：可指向域、最大位移、固定宽度、业务唯一归属、需求守恒、要求的覆盖条件及修复预算。只对通过检查的完整候选赋予非零概率。

不能用三个独立动作头各自 mask 后假定组合一定合法。首版对联合候选做一个 categorical 分布，另加始终有效的 `STOP`。

初始布局不可行时先由非学习模块修复；仍不可行则报告失败，不能让 STOP 把非法布局标成成功。达到预先定义的最大调整步数属于该有限任务的终止。

如多个请求修复为相同布局，首版可保留它们并记录重复率；去重时必须在采样前完成并固定候选 ID，不在采样后合并概率。

## 5. PPO 与修复的正确衔接

记请求动作是 `a_t`，修复映射是 `T_fix(s_t,a_t)`。环境把修复后的合法布局作为下一状态，奖励按该布局完整调用冻结第二阶段后计算。

rollout 同时保存请求动作、执行布局、修复轨迹、当时的候选表、mask、旧 log probability、状态版本和下游评价缓存键。

PPO 概率比必须是 `ρ_t=π_new(a_t|s_t,mask_t)/π_old(a_t|s_t,mask_t)`，不能把执行后的布局编号冒充策略直接采样的动作。

训练更新复用采样时的候选表与 mask，不能用更新后的生成器重新编号候选。确定性修复版本须固定；确需随机修复时，其随机状态应纳入环境可复现记录。

采用标准 clipped PPO 目标 `E[min(ρ_t A_t, clip(ρ_t,1−ε,1+ε)A_t)]`，价值函数预测同一覆盖任务回报。裁剪不等于约束保证，硬约束仍由联合 mask 和校验执行。

这里的“约束 PPO”指可行候选上的 PPO，并未实现 CPO 的理论保证，也不宣称每次网络更新都满足信赖域约束。

## 6. 奖励和最终选择

对同一 root，总原始需求为 `D_root=Σ_u d_u`，每个候选下游终局速率为 `R_b`，聚合需求为 `D_b`：

```text
J_root(L) = Σ_b min(R_b(L), D_b(L)) / D_root
F(L) = J_root(L) − λ_move · C_move(L,L_initial)
r_t = κ · [F(L_{t+1}) − F(L_t)]
```

`C_move` 使用按预先约定角位移尺度归一的非负代价，`λ_move` 由验证集选择并冻结。若只研究静态布局，主结果先取 `λ_move=0`，移动代价另报。

固定有限步数下使用 `γ=1`，环境回报望远镜求和到终局目标差；GAE 或 PPO 近似优化本身不提供全局最优保证。STOP 产生零布局增量并结束回合。

不以第二阶段的逐束平均满足度 `U` 排序不同布局：覆盖划分改变束需求与束数时，`U` 的统计对象会变化。`J_root` 将未覆盖业务保留在共同分母。

无正需求的 root 不计算上述比值，单列空业务流程。缺 root 或 assignment 时不构造虚假 `J_root`，只做接口演示。

## 7. 训练与计算安排

先用便宜容量代理预训练候选选择，再以冻结 T-SAC 的 `J_root` 微调；必须分别报告代理阶段和最终真评阶段，代理得分不能替代最终业务指标。

“真评”仅指实际调用当前第二阶段和物理内核完整重算，不代表真实卫星实测。缓存键至少包含 root、候选、需求、配置、权重和服务顺序 hash。

每个覆盖动作至多执行一次下游完整分配，初始布局还需一次评价；候选可行性检查不需调用第二阶段。设轨迹步数为 H、一次下游评价成本为 `C_alloc(B)`，未命中缓存时成本约为 `(H+1)·C_alloc(B)` 加候选生成、图编码和全部候选的可行性修复成本。即使只执行一个动作，为构造mask而修复其他候选的开销也必须计入。

图稀疏边数为 E 时，普通消息传递每层约随 E 增长；全注意力一般随 B² 增长。实际瓶颈要测量，不能仅凭图网络结构声称实时。

## 8. 必做对照与消融

1. 同一初始布局、同一候选集合的随机合法调整、即时贪心、束搜索或局部搜索，与 PPO 比较。
2. 分别按相同下游调用次数和相同墙钟时间比较；单独计入 PPO 离线训练与标签成本。
3. MLP/集合池化与图编码器比较，去掉边耦合特征，检验图结构是否真的有用。
4. 仅代理奖励、仅 `J_root`、代理预训练再 `J_root` 微调比较，检验预训练是否造成目标偏移。
5. 有无 STOP、不同调整步数、不同移动代价、是否允许跨簇边界归属的消融。
6. 保留同一硬约束，比较完整修复与较简修复；记录修复成功率、重复候选率及每步修复时延。

学习路线先用 3 个独立训练种子筛选，最终主结果建议不少于 5 个种子；按独立 root 或完整轨迹做成对统计，不能把一个 root 的候选当成独立样本。

测试覆盖热点、多热点、长尾、不同总负荷与几何可行规模。170/220 等规模是否列为留出点，应与第二阶段已冻结的数据划分一致，不能在第一阶段重新混入训练。

## 9. 风险与止损

最大风险是下游调用昂贵、图特征贡献小、PPO 只学到已有贪心规律，或覆盖变化把冻结分配器推到训练域外。

如果相同真评预算下 PPO 不能在独立验证 root 上稳定超过局部搜索，应停止扩大网络，保留候选生成与修复，把学习器退为候选排序模块。最终测试只用于报告冻结方案；根据测试结果开展新一轮方法设计时，应另留新的最终评估数据。

如果所有覆盖算法在某类场景上都因冻结分配器失效而下降，应先报告分布外问题；另做全方案同预算的第二阶段再训练实验，不让某个覆盖方案单独获得微调优势。

如果收益主要来自违反固定宽度、篡改频组或漏记未覆盖需求，则该结果直接作废，不作为调参依据。

## 10. 最小可运行版本与验收

第一批：可追溯合成 root、固定宽度可行初值、8 个方向中心微移、确定性归属与修复、联合 mask、STOP、冻结下游适配器。

第二批：共享 MLP 的 PPO、请求/执行双日志、终局 `J_root`、相同调用预算贪心基线；先证明链路与优势估计对应正确，再引入图网络。

验收要求包括需求守恒、动作非法时不提交、mask 重放一致、请求动作 log probability 对齐、行置换一致、同root不跨数据分区，以及候选全量物理重算通过。

目前真实上游 root 与 assignment 尚缺。合成生成器必须保存种子、版本、几何规则和需求规则并标注合成，不能从历史聚合 CSV 反推一组“真实用户”。
