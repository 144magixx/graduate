编制日期：2026-09-20。版本：v1。依据：当前已落地的 `horizon_tsac_20260920` 实现、第二阶段实施记录及既有覆盖调研。本文提供六套可选研究方案和推荐组合；本轮交付为方案文档，未实现第一阶段、生成训练集或验证性能提升。

配套文件：[第一阶段接口与实施规范（面向实施Agent）](<D:/graduate/第一阶段波束覆盖方案/第一阶段接口与实施规范（面向实施Agent）.md>)；[研究依据与适用边界](<D:/graduate/第一阶段波束覆盖方案/研究依据与适用边界.md>)。

## 1. 我的建议：把第一阶段做成“面向可交付业务的覆盖优化”

第一阶段决定波束放在哪里、哪些业务归属于哪些波束，以及经物理核验后允许使用的波束宽度和数量；第二阶段在这个布局上分配连续频谱块与离散总功率。第一阶段真正要回答的是：**在相同原始业务、载荷和总功率预算下，什么覆盖布局能让下游交付更多业务，并保护难服务区域？**

最推荐的组合是：**方案一建立合法覆盖生成器 → 方案三建立冻结第二阶段的候选评价与搜索 → 如果论文需要 DRL 主线，再做方案四。** 方案二是可解释、成本较低的增强和强基线；方案五、六按研究侧重点择一扩展，不建议六条线同时开展。

若必须从六套中选一条论文主线，推荐“资源感知的残差覆盖决策”：先用可解释方法生成可行布局，再由第一阶段策略逐步调整，最终用冻结 Horizon T-SAC 的业务交付结果评价。其创新应落在**覆盖与下游资源可服务性的联系、约束动作设计和跨场景验证**，不能只把“用了 GNN/PPO/Transformer”作为创新。

```text
原始业务 root：用户/业务点、需求、服务区、来源谱系
  → 第一阶段：合法布局＋唯一业务归属＋多个覆盖候选
  → 第二阶段：冻结 Horizon T-SAC，分配频谱块和离散功率
  → 共同分母评价：J_root、漏覆盖、资源违约、计算成本
  → 第三阶段（可选联评）：固定频谱的连续功率精修
```

## 2. 当前第二阶段对第一阶段意味着什么

### 2.1 应沿用的新能力

- 新链路是 `PPO4090/implementations/horizon_tsac_20260920/`。`CoverageScenario` 使用可变长波束实体数组，区分真实实体、正需求和 padding，不要求第一阶段固定输出 200 行。
- 已有 `RootScene`、`CoverageCandidate`、需求守恒/球面归属校验，以及 `allocate_candidate(root, candidate, policy, physics_config)` 的直接调用接口。
- 第二阶段默认有 8 个逻辑资源池、100 个共享物理频槽，单槽 25 MHz；每束选择连续 1–10 槽、5–50 W 十档总功率或 SKIP。总预算默认 6000 W，不随第一阶段波束数自动变化。
- 同池同槽禁止重叠；不同池的同极化波束仍有同频干扰。第一阶段的重叠与几何布局因此会影响下游分配，不能把“不同 group”当成天然无干扰。
- 第二阶段内部主效用是正需求波束的平均截断满足度 U，奖励为 `100ΔU`。跨覆盖候选应另用原始业务共同分母的 `J_root`。

依据：[配置](<D:/graduate/PPO4090/implementations/horizon_tsac_20260920/config.py>)、[覆盖实体契约](<D:/graduate/PPO4090/implementations/horizon_tsac_20260920/data/schema.py>)、[root/candidate 接口](<D:/graduate/PPO4090/implementations/horizon_tsac_20260920/data/domain.py>)、[候选评价接口](<D:/graduate/PPO4090/implementations/horizon_tsac_20260920/evaluate.py:40>)。

### 2.2 应先补齐的边界

1. **真实上游数据缺口。** 当前工作区没有可重建原始业务和归属的覆盖生成器；100 份旧 CSV 是聚合结果，不能逆推出唯一的真实用户分布。第一阶段首先要建立可追溯的 root 和生成器。
2. **物理能力不等于程序可接收范围。** 48–256 个正需求波束是待确认的建设域，不能把可变数组或测试 fixture 当成已验证部署能力。`N_entity`、`N_demand` 与硬件可同时开启波束上限分别记录。
3. **宽度语义必须修正。** 新接口的 `ground_diameter_deg` 是地面球面圆盘的角直径，绝不是天线半功率角。球面半径为 `R_earth × π × ground_diameter_deg / 360`；地面角直径 1°对应约 55.6 km 半径。不能直接搬用旧调研中天线角宽的数值。
4. **可变宽度暂不作为首版自由动作。** 当前物理核提供逐束峰值增益字段，但默认峰值固定，没有经过验收的“变宽—峰值增益—旁瓣—硬件可实现性”联动。首版固定宽度；后续用独立物理 profile 验证变宽，并重新评价或训练第二阶段。
5. **冻结策略的质量仍需建立。** 现有短训练证明工程链路，不能当作成熟资源分配器。接口跑通可先用确定性贪心，正式第一阶段结论须绑定通过独立验证的第二阶段 checkpoint。
6. **中心聚合仍是代理。** 当前每束用中心位置与聚合业务计算链路，不是逐用户调度。`J_root` 只能称“聚合可交付业务比例”；边缘用户真实吞吐需要额外用户级评价。

既有 [第一部分调研](<D:/graduate/research_outputs/2026-09-20/第一部分波束覆盖调研与落地方案.md>)保留为历史材料。其中固定 200 行模板、旧 fyh_IO 串联和部分宽度示例，不再作为本轮新链路的实施默认。

## 3. 六套方案分别解决什么问题

### 方案一：容量约束聚类与全覆盖修复——稳妥起步

以需求加权聚类产生中心，再做唯一归属、过载修复和覆盖修复；输出多初值的合法候选。它先解决“有没有可信上游”的问题，能给第二阶段提供真实谱系的数据，也能成为其他方案的共同起点。

优点是可解释、调试容易、无需训练；局限是容量代理未必准确，单纯聚类可能制造干扰。新增实现工作量相对最低，但原始业务与物理规格仍是前置条件。

详见：[方案一-容量约束聚类与全覆盖修复](<D:/graduate/第一阶段波束覆盖方案/方案一-容量约束聚类与全覆盖修复.md>)。

### 方案二：干扰图引导的拆分合并与局部搜索——低成本增强

把波束间的方向图耦合构成图，对“高负载且强干扰”的局部区域进行移动、重关联、成对拆分合并，再调用第二阶段验收收益。拆分合并首版保持总实体数不变，避免把增加硬件数量混成算法收益。

优点是直接利用当前物理模型，可解释为什么某个布局更适合频谱复用；局限是图分数只是代理，不能代替实际分配，稠密布局可能陷入局部最优。适合作为强非学习基线，也可以独立形成研究线。

详见：[方案二-干扰图引导的拆分合并与局部搜索](<D:/graduate/第一阶段波束覆盖方案/方案二-干扰图引导的拆分合并与局部搜索.md>)。

### 方案三：冻结Horizon T-SAC的双层候选搜索——优先推荐

上层搜索覆盖参数，下层调用固定版本的 Horizon T-SAC。用便宜代理筛掉明显差的候选，再用真实分配结果排序，保留业务交付与计算成本之间的非支配候选。

这是目前最容易把两个阶段连成研究问题的路线，不必先训练另一个智能体。主要代价是第二阶段调用次数；主要风险是针对某个下游策略的弱点过拟合。需要等预算比较、独立分配器复核，以及对代理漏选的审计。

详见：[方案三-冻结Horizon T-SAC的双层候选搜索](<D:/graduate/第一阶段波束覆盖方案/方案三-冻结Horizon T-SAC的双层候选搜索.md>)。

### 方案四：残差式图策略与约束PPO——推荐DRL主线

从方案一的可行锚点出发，一步选择“一束/一个局部操作”或 STOP；通过联合动作 mask 保障可行性，用冻结第二阶段的 `J_root` 增量学习如何改善布局。先共享 MLP，再加入图编码做消融。

它的价值是把昂贵搜索摊到离线训练，争取快速在线决策；风险是下游评估昂贵、回报稀疏及策略只适应训练布局。只有在与方案三等在线预算比较后，才有必要保留 RL 的复杂度。

详见：[方案四-残差式图策略与约束PPO](<D:/graduate/第一阶段波束覆盖方案/方案四-残差式图策略与约束PPO.md>)。

### 方案五：业务不确定性与滚动鲁棒覆盖——偏动态研究

在需求预测有误时，选择平均交付好且坏场景损失可控的布局；先做静态多需求场景，再研究滚动更新与事件触发，抑制频繁重构。第二阶段逐快照重跑，不把它误称为已有队列控制器。

它适合将来有航空、热点迁移等时间序列的情况；没有可信时间数据时，只能做明示的合成动态研究，不能报告真实在线收益。

详见：[方案五-业务不确定性与滚动鲁棒覆盖](<D:/graduate/第一阶段波束覆盖方案/方案五-业务不确定性与滚动鲁棒覆盖.md>)。

### 方案六：候选排序蒸馏与快速覆盖决策——偏部署效率

让方案三生成教师候选及真实 `J_root` 标签，训练模型对同一 root 内的合法候选排序；部署时只对少量高分候选做真实第二阶段复核。无需模型直接生成高维中心坐标，能降低非法输出和布局置换歧义。

它适合候选搜索有效但在线太慢的情况；新增模型是否值得做，取决于候选分布外的漏选率和实际加速，不能只报告排序准确率。

详见：[方案六-候选排序蒸馏与快速覆盖决策](<D:/graduate/第一阶段波束覆盖方案/方案六-候选排序蒸馏与快速覆盖决策.md>)。

## 4. 统一目标：几何覆盖、业务归属与可交付业务分开评价

设原始业务点为 `k=1…K`，需求为 `d_k`；候选波束为 `b=1…B`，归属为 `A_kb`。首版使用 0/1 唯一归属，要求 `Σ_b A_kb ≤ 1`，且正归属必须落在合法覆盖范围内。

```text
D_b = Σ_k A_kb d_k
D_unassigned = Σ_k (1 − Σ_b A_kb) d_k
Σ_b D_b + D_unassigned = Σ_k d_k

C_geo = 有至少一个合法波束覆盖的业务点数 / 待服务业务点数
C_demand = Σ_b D_b / Σ_k d_k
J_root = Σ_b min(R_b, D_b) / Σ_k d_k
U = 正需求波束上 mean(min(R_b / D_b, 1))
```

`D_unassigned` 与当前接口的 `uncovered_demand_bps` 对应，包括未获得归属的业务；几何有覆盖但没关联也不能当作已服务。原总需求为零时，需求比例和 `J_root` 返回不适用，单独记录空业务场景。

**先满足约束，再比较业务效用。** 若任务要求所有业务点全覆盖，主实验要求每个目标点都有合法归属；只达到 99% 需求覆盖不能写“全覆盖”。找不到可行解时保留诊断及未覆盖量，不能通过删用户、扩大到未获准宽度或复制波束掩盖失败。启发式搜索失败只叫“未找到可行解”；有求解器证书或必要条件证明时才称“已证不可行”。连续服务区域全覆盖比有限业务点全覆盖更强，需要网格/几何证书另验。

跨候选不能单独看 U。例如同一总需求 100 的示意问题中，候选甲的两束需求为 90、10，交付为 54、10，则 U=0.80、J_root=0.64；候选乙需求为 50、50，交付为 37.5、37.5，则 U=0.75、J_root=0.75。第一阶段应偏向乙。此例只是指标反例，不是物理仿真结果。

负载均衡是解释变量，建议看 `D_b / Ĉ_b` 的负载率，而不是只看 `D_b` 方差。`Ĉ_b` 是显式容量代理，不是已保证容量；代理失配也应记录。

## 5. 几个值得重点验证的点子

### 5.1 “多一束”未必更好

拆分热点能减轻单束负载，却增加资源池占用和干扰。保持总功率固定，比较不同合法实体数量下的 `J_root`，再观察新增一束的边际收益；先以固定 B 做主实验，再以可变 B 做独立扩展。不能把增加波束与增加总功率同时进行后归因于布局优化。

默认 6000 W、单束最高 50 W 时，`N_demand ≤ 120` 的场景不会因“所有束都选最高档”而超总功率预算。此时结果主要可能由频谱/干扰主导。功率竞争实验应使用合法的大规模候选或明确命名的低预算 profile，不能暗改主预算。

### 5.2 只对“值得问第二阶段”的候选付计算成本

先用守恒、几何和干扰代理筛选；再用相同版本的下游真评估排序。保留少量代理低分的随机审计候选，测量漏掉好布局的比例。最终交付的布局必须有真实第二阶段评估记录，而非仅有代理预测。

### 5.3 把“资源稀缺在哪里”反馈给覆盖

观察第二阶段的缺口、跳过、占用与受干扰程度，驱动局部移动或归属修复。反馈是优化启发，不等于可证明的对偶价格。可以用有限次反事实试探估计某个局部操作的收益，再判断代理是否可靠。

### 5.4 候选多样性本身也是第一阶段交付

每个 root 除最优布局，还保存普通与较差但合法的候选，覆盖重叠、负载、尺度和资源压力的变化。非法几何或重复业务属于错误样本，不能混成“困难训练样本”。不同候选都留在该 root 的同一数据分区。

### 5.5 用第二个分配器验证覆盖收益是否可迁移

主线冻结一个 Horizon checkpoint；再用确定性贪心或另一个独立训练 seed 的 checkpoint 评价同一最终布局。若收益只在搜索使用的那个策略上存在，应解释为特定策略适配，不能上升为普遍物理优势。

## 6. 推荐实施顺序与退出条件

**第一批：接口与非学习闭环。** 冻结服务区/宽度/预算等 profile，接入可追溯 root，完成方案一与确定性贪心串联。验收需求守恒、覆盖归属、稳定 ID、root 隔离和落盘重载。

**第二批：建立可靠评价器。** 用多样合法候选训练/验证第二阶段，冻结权重、配置、数据版本；方案二作为强基线，方案三建立等调用预算的搜索比较。此批回答“资源感知覆盖是否有用”。

**第三批：只选一条学习主线。** 若 DRL 是论文要求，做方案四；若重点是低推理成本，做方案六。达到可行性但没有统计可辨认收益时，保留非学习方法，不通过换测试集或隐藏失败种子追逐正结果。

**第四批：按需要扩展。** 有时间序列再做方案五；有宽度—增益标定再放开宽度动作；第三阶段只作为固定附加模块联评。每次只增加一种机制，并单列消融。

这些是工作批次，不是已经执行的进度，也不是未经实测的工期承诺。

## 7. 统一实验要求

- 共同基线：固定规则布局＋合法归属/修复、需求加权聚类＋相同修复、方案一、方案二；涉及学习时增加等候选预算随机搜索/局部搜索。
- 所有方法使用相同 root、硬件数量、覆盖约束、物理 profile、总预算和下游版本。规则布局若覆盖失败，如实列失败，不删除该 root。
- 指标至少包括 `J_root`、需求/点覆盖、未归属需求、U、低分位 root 表现、违约、实际下游调用次数、生成与推理总耗时。用户公平性须有独立用户调度定义，不能把按束公平性改名。
- 消融依次考察容量代理、干扰图、真实下游反馈、图编码、残差锚点和鲁棒项。每组只改其声明的因素。
- 首先固定 B 和宽度建立因果清楚的结果，再单列变规模实验；48–256 需先证明上游可行。未见尺寸、未见 root、未见地理/业务族分别报告。
- 按 `split_group_id` 隔离共享母场景与时间片谱系。增强、搜索轨迹、教师标签都继承 root 的 split。候选数不能充当独立样本数。
- 用 root 配对差值评价，置信区间按独立 root/谱系重采样；学习算法同时报告训练种子差异。建议正式阶段采用至少 5 个训练种子，先评估计算成本。
- 测试时允许执行事先冻结的候选搜索算法；禁止依据测试集整体结果再调权重、预算、候选族或停止阈值。搜索调用成本必须计入该方法。
