# T-SAC 可变波束规模与泛化训练方案

本方案根据你提出的“200 束训练后用于 170/220 束、资源固定、顺序依赖和随机数据真实性”要求补充，并作为代码重构的核心验收要求。它适用于用户确认的 fyh_IO 路径；本次只提出设计，不修改代码或启动训练。

## 1 先明确哪些问题需要改变

你的担心有根据，但不能由“回合固定步数”直接断定模型没有泛化性，也不能靠增加随机数据就证明泛化。当前有四个不同层面的问题：

1. **接口规模兼容性**：环境固定 `beam_num=200`，输入被补齐或截断，循环/预算/终止依赖该常量。这会先阻止合法的 170/220 束实验。
2. **可用决策信息**：目前 205 维状态主要是当前束、剩余功率和频谱状态；14 个 token 不是 200 个波束 token。模型并没有因此自动获得全部待服务波束的需求和几何关系。
3. **训练分布覆盖**：固定规模、固定的预算生成关系、固定需求排序及有限布局增强，可能让策略记住这些规律。单次独立噪声无法代表移动热点、连续雨衰和业务突发。
4. **物理资源变难**：总功率不变而波束/需求增加，系统本来就更难服务。平均满意度下降不一定全部由泛化失败造成，要与同一新场景下的启发式、优化和目标规模重训策略对比。

现有每回合的“按束逐步分配”是构造一个业务快照方案的计算过程，不一定是物理时间。它可以用于真实调度；关键是能否适配不同输入，是否给了足够的全局信息，以及最后是否用同一物理模型验证。真实时间上的业务演化应另设外层轨迹，不能把随机换束顺序当成动态业务。

## 2 推荐的总体方案

**先把环境改成可变有效束数，再混合多种规模与资源压力训练；状态用波束集合/图表达，频谱保留物理顺序；先减少人工顺序依赖，最后才学习调度顺序。**

建议分四个版本，并保持清楚的贡献归因：

- `G0`：环境支持变长、功率预算独立配置、统一 valid mask，保持现有策略网络作兼容基线。
- `G1`：混合规模/预算/需求/拓扑训练，加入剩余待服务需求和数量等全局信息；先用集合池化作为低成本状态增强。
- `G2`：波束集合或图编码器 + 原频谱编码器，显式学习跨束干扰和未来资源竞争，保留相同训练分布比较架构收益。
- `G3`：在完整需求轨迹上训练/评估，加入重配置代价、队列/时延和真实位置数据校准；必要时再训练“下一束选择器”。

混合规模训练和变长网络是不同改进。用 `G0/G1/G2` 逐个验证，才能知道提升来自数据还是架构，避免一次更换全部组件却无法解释收益。

## 3 环境怎样支持 170 和 220 束

### 3.1 取消模板行数的物理含义

`Scenario` 显式提供 `beam_ids`、`valid_mask`、`demand_bps`、布局和 `p_total_w`。有效实体数量来自输入数据，不再由模块级 200 决定。若 170 个有效束在张量中 padding 到 224，回合仍只有相应的真实分配任务；如果 220 个有效束，不能截掉后 20 束。

必须区分三种 mask：

- `valid_mask`：这是不是一个真实的场景实体，padding 为假。
- `pending_mask`：这个有效束是否尚待处理。
- `served_mask`：是否获得服务，只用于描述结果。

有需求但未服务的束仍必须进入评价，服务量按零计；不能因为未点亮、无可用槽或功率不足就从分母排除。零需求束若确实存在可保留其几何实体，但业务比值评价单独排除并报告计数，不能和 padding 不加区分。

总功率不再自动等于 `N×30`；训练采样器决定它，环境仅执行这个预算。`Pmax`、槽数、频组、槽宽也通过配置提供。第一阶段保持频谱维度不变，专注束数泛化，不同时宣称可适应任意频段/载荷。

### 3.2 结束规则

一个快照的分配在全部有效任务处理完、显式停止、或再没有合法分配时结束。无资源的真实需求保留为未满足。算法人为设置的时间/步数限制使用 `truncated`，真正任务结束使用 `terminated`；如果是延续任务的截断，学习时应按相应定义 bootstrap，不能混用一个 done。

所有终止路径均先形成一致的最终分配，再计算全场景指标。预算不足时直接阻止非法功率，而不是先执行超预算动作再结束。允许合法的“不服务/零功率”动作，使资源耗尽后的问题仍有定义。

## 4 状态与网络怎样设计

### 4.1 最小增量版本

先保留原 100 频率槽编码，补充这些全局量：有效束数、待处理束数、待处理总需求与需求分位数、剩余功率/总功率、剩余功率/待处理束数、剩余可用频谱比例，以及未来束对当前候选频段的竞争统计。

例如同样剩余 100 W，后面只剩 2 束和还剩 50 束，需要不同决策。如果观察中不能区分，训练更多样本也无法可靠学到这种差别。上述摘要只是低成本近似，不保证完整 Markov 性；后续用完整波束集合补足。

增加输入特征会改变网络接口，旧权重只能作为对照或经过显式适配初始化；不能把未验证的补零输入称作无损迁移。

### 4.2 推荐双分支结构

```text
变长波束集合 [N, F_beam] + valid/pending mask
  → 共享 MLP + masked pooling（首版）
  → 可选稀疏干扰 GNN / 无编号位置编码的 Set Attention
                         ┐
频谱与占用 [G, S, F_slot] → 频谱 Transformer ├→ 当前束条件融合
全局预算与负载向量                         ┘
  → 条件化的频率起点、槽长度、功率动作
  → 联合动作 critic / 明确验证过的近似 critic
```

波束节点含物理位置/视线、需求、宽度、增益、关联/频组、已分配资源和 pending 状态；边含有方向的交叉增益及重叠/干扰关系。相同参数处理任意 N，批内采用动态 padding 或图批处理。

波束编号没有物理意义时，不加入“第 1、2、…、200 束”这种可学习绝对位置 embedding；物理坐标与几何关系应保留。频率槽不同：相邻频率及连续块有物理意义，频谱位置编码需要保留，不能为了置换不变而删掉频率顺序。

对波束列表做一致的重新编号，节点输出应随之重新编号，全局值函数保持不变。这称为置换等变/不变；它减少对任意输入编号的依赖，但**不意味着改变实际服务顺序不会改变资源分配结果**。[Deep Sets](https://arxiv.org/abs/1703.06114) 与 [可扩展无线资源管理 GNN](https://arxiv.org/abs/2007.07632) 提供了结构依据，不能代替本 HTS 模型的泛化实验。

池化不要只用 mean 后丢掉总负载。可同时保留 masked mean、sum、max 和 N/总需求等全局特征。图邻域截断可以降低编码成本，但最终干扰计算仍使用全部有效边，或单独量化近似误差。

### 4.3 动作与约束

第一版仍逐束分配，采用条件动作：`π(start|state) → π(length|state,start) → π(power|state,start,length)`。后续每个条件下重新计算可行 mask，保证块不越界、不撞同组已占槽且功率不超预算；mask 参与采样、log-prob、entropy 和 target 的同一分布定义。

固定物理频组映射应存储在稳定 `beam_id` 或独立规划结果中；随机打乱输入时不能再次用新的行号 `%8` 改变频组，否则同时改变了调度顺序与干扰问题。若要学习频组分配，应作为单独动作扩展和实验。

可行集合随 N/资源变化时，其最大熵也变化。温度目标要与 mask 后的动作空间和条件熵定义一致；不继续沿用缺少符号说明的固定 `-6.9`。不允许通过随机动作熵奖励诱导无意义延长回合。

## 5 怎样训练才有希望提升泛化

### 5.1 场景采样

每个 episode 随机抽取的应是一个**物理一致场景**，包括规模、拓扑、预算、负载、需求过程、覆盖宽度和信道；不是对每列独立加噪声。

建议首版训练有效束数取 `{50,80,100,130,160,190,200}`，170 专门留作未见规模插值测试，220 留作超过训练最大规模的邻近外推，250/300 为更远外推。验证可另留 180，用于调参；不使用最终 170/220 测试集选择 checkpoint。这个集合是启动建议，后续根据场景可行性和计算量调整，调整后重设独立测试。

资源负载不能只用固定 6000 W：根据卫星配置的合理范围采样总功率、总需求、热点强度和空间密度，覆盖欠载、接近饱和及过载场景。先用先导仿真校准容量代理，再按 offered load 分层；不要先给任意区间就称其“真实”。载荷功率上限本身不会无故每分钟大幅跳变，预算随机化代表跨配置/故障/策略可用预算的训练覆盖，与时间动态区分。

### 5.2 真实数据的作用

实际可获得的是城市位置、用户/航迹、区域业务统计及天气等不同层级的信息。先用这些校准位置密度、需求长尾、热点移动速度、日周期和空间相关性，再生成足量训练场景。真实轨迹留出完整日期/航线/区域作外部测试。

不能把 ADS-B 直接当吞吐需求，也不必等待运营商全量数据才开始。可采用“真实几何/轨迹 + 明确的需求模型 + 相关雨衰”训练与评估；报告中分别展示合成域和真实位置域结果。无法观察的未来需求只能用因果预测输入，不能把整条测试轨迹未来值送给策略。

### 5.3 顺序训练

先保留需求降序基线，同时训练随机顺序与少量物理启发式顺序混合，例如需求缺口优先/强干扰优先。数据 split 固定后才在各自内部生成排列。测试时同时报告固定顺序、随机顺序分布和最差顺序表现。

排列增强应联合重排几何、需求、关联、已分配状态、邻接矩阵和 ID 映射，保持同一个物理问题。多序搜索可提升性能，但 K 个顺序就应计 K 次推理成本。

如果策略在不同顺序下仍差异大，再引入 per-beam pointer 选择下一束，或先生成完整方案再做固定轮数局部修正。这是新算法设计，不作为第一轮重构的必要负担。并行输出所有功率/频率也不是自动更好，仍需解决共享约束和频谱碰撞。

### 5.4 变长回合的训练细节

不同 N 的回合长度不同。按 transition 均匀回放会让长回合占更大权重，建议先抽规模/场景桶，再抽其中 transition，并记录实际采样分布。新状态、动作或物理模型不能与旧 replay 无版本标记混用。

在静态一次性分配任务中，主目标是最终完整分配效用 U。可使用全场景效用差 `r_t=U(plan_t)−U(plan_{t−1})`，每步重算包括历史束受干扰后的变化；未分配真实需求也保留在 U 中。在有限、无循环、显式终止的 construction episode 中，`γ=1` 时效用差可望远镜求和为终局效用差。若仍采用折扣，需使用相应的势函数形式或明确时间偏好，不得宣称任意差分奖励在 `γ<1` 下仍等价。熵正则会进一步改变训练目标，应以不含熵的真实 U 评价。

如果一个完整快照代表固定物理时间间隔，却坚持逐束内部折扣，可比较 `γ_N=γ_round^(1/N)`；这是明确的建模选择，不能和真实动态时隙的折扣混为一谈。总 SGM 与平均 SGM代表不同目标，按 N 归一后要明确采用的是哪一种。

现有代码的SGM尺度β还取总需求除以模板束数；改变padding/束数会同时改变指标本身。应将β的定义与业务有效集合写入指标版本，在跨规模实验中同时报告固定物理尺度β与明确的相对尺度口径，不能让指标改变制造泛化收益。

输入归一使用固定物理尺度、需求/容量比例、剩余/总预算和局部角距等，同时保留必要的绝对规模。归一统计仅从训练集拟合，测试时冻结。比较固定规模与混合规模时按相同有效交互步数/计算预算控制成本，不能仅让两者都训练 4000 回合。

## 6 170 和 220 束应怎样评估

先固定同一个 checkpoint，完全不更新参数、温度和归一统计，做零样本测试。再单独进行有限预算微调，报告额外样本数、时间及独立测试结果。两者不能混报为泛化。

每个规模至少分三组：

1. **总功率固定，单束需求分布相同**：束数增加导致总需求增加，测资源竞争/过载。
2. **总功率固定，总需求固定**：需求重新分布到更多束，测空间划分、干扰与维度变化。
3. **总功率和总需求都近似随 N 缩放**：每束平均资源类似，测规模迁移；这不代表同一颗卫星可随意增加载荷能力，只是控制变量实验。

还要区分同一区域增加波束带来的密集干扰，与区域扩展、相近局部密度的大图扩展。两者是不同难度。

最小消融顺序：固定200基线 → 仅变长/混合N → 再加预算与负载变化 → 再加顺序增强 → 再加集合/图状态 → 最后真实轨迹校准。用同一物理模型比较，若同时修正了功率模型，应先在新物理模型下建立固定200基线。

必须报告：预算/频谱约束违反率、业务缺口、平均与5%满足率、总/平均SGM、推理时间、每个场景失败原因；同时给相同目标规模的强启发式/连续精修基线。目标规模专门重训的模型是参考性能而非数学上界。

## 7 直接纳入重构的验收条件

- 170、200、220 个有效束均能完成分配；220 不截断，170 不复制为200个“真束”。
- 同一有效场景 padding 到不同长度，不改变有效动作分布与业务指标（数值容差内）。
- 一致重排波束 ID 后，网络输出满足相应等变关系；固定频组不随存储行号改变。
- 总功率、总需求、有效束数可独立配置；配置 manifest 中分别保存。
- 整个 actor/critic/replay/collate/指标链理解 valid/pending mask，不能只在 attention 上加 mask。
- 训练和测试的规模、几何、轨迹、预算及种子分割可追溯；零样本与微调明确分开。
- 对用户最关心的 170/220 给出独立留出曲线，而不是只展示训练 reward。
- 工程上线有独立约束检查和可行回退；优化回退提高可行性，不能据此掩盖原策略性能退化。

可变规模架构提供“能处理”的条件；多域训练提供“见过相近变化”的机会；独立留出测试才提供“在这些范围内有效”的证据。即使全部完成，也不应声称对任意波束数、任意卫星和任意业务分布都有效。
